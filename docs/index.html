electronic-trading

A research platform for executing large orders at low cost and making markets profitably. It starts from the canonical models (Almgren-Chriss optimal execution, Avellaneda-Stoikov market making, implementation-shortfall analytics) and builds towards what decides money in practice: realistic costs, informed flow, fees and ticks, fair-value signals and post-trade measurement. Implemented in Python, C++, Rust and Java from one pinned contract, cross-checked by shared golden values in CI on Linux, Windows and macOS.

What's inside

Almgren-Chriss execution

Closed-form optimal sell trajectory (kappa, holdings x_j, trades n_j) for linear temporary and permanent impact under an arithmetic random walk, with exact discrete E[IS] / Var[IS] sums as the single code path for optimal, TWAP, POV and hand-built schedules. x_N = 0 is forced exactly; the lambda_ra = 0 TWAP limit is an explicit branch.

Frontier & baselines

Efficient-frontier sweep over a risk-aversion grid with half-life (1/kappa, an e-folding time) reporting; TWAP, POV and instantaneous-liquidation baselines on the same cost model; a Monte Carlo IS simulator whose mean and variance must land within 4 SE of the closed forms. Sell programs only (X ≥ 0); the paper's fixed cost term is omitted and documented.

Avellaneda-Stoikov market making

Reservation price, optimal spread (2/γ)·ln(1 + γ/k) and quotes; exponential arrival intensity A·exp(−k·δ) with thinned-Poisson fills; a simulation loop with pinned draw order, hard inventory cap, terminal liquidation penalty and an optional volatility stress after T/2. A fixed-spread comparison agent shares the same RNG mechanics.

Execution analytics

Perold (1988) implementation-shortfall decomposition into delay, trading and opportunity components for buy and sell orders (with the identity and price-shift invariance tested), participation rate, and a native two-variable OLS used to fit cost-per-share against participation on pinned RNG-free synthetic fills.

Post-trade TCA

Slippage against arrival, the day's VWAP, the interval VWAP of the bins the order traded in, and the close; markouts per fill and per share; per-bin participation; a Welch t-test for comparing algorithms, with the incomplete beta and Student t CDF pinned so every port gives the same p-value.

Calibration from recorded data

Volume curve, realised-volatility curve, spread statistics and a weighted fill-intensity fit on plain arrays; three presets and a volume curve fitted to the NASDAQ ITCH sample day 2019-12-30, with only aggregates committed.

Execution extensions

Transient impact with exponential resilience (Obizhaeva-Wang), its optimum from one tridiagonal solve; adaptive re-planning against the static schedule under a drift signal or partial fills; internalisation of opposite client orders.

Market making with frictions

The A-S quoting logic with a price grid, maker fees or rebates, stale quotes, informed traders and a fair-value signal, switched on one at a time; GLFT quotes beside A-S; every path's PnL split exactly into spread, fees, inventory and liquidation, with one-step markouts.

Limit-order placement

Fill probability of a resting order from its place in the queue; the choice between posting and crossing for a child order; liquidation with limit and market orders by backward induction, checked against all-market and post-then-sweep on shared paths.

Golden-value testing

Eight golden files with 95 cases (19 model, 15 market, 8 impact, 11 TCA, 9 calibration, 8 execution, 14 market-making, 11 placement), loaded by all four suites: deterministic cases under a relative-or-absolute tolerance of 1e-9 to 1e-12, Monte Carlo cases as reference values plus standard errors. Sample values differ across languages by design; distributions must agree.

Property, numeric and validation tests

Per language: trajectory monotonicity, inventory cap respected at every step, frontier monotonicity, continuity across the TWAP branch, overflow safety at kappa·T > 2500, ac_kappa_small_tau at millisecond tau, and every rule in API_SPEC §6 — NaN/inf, empty grids, non-liquidating schedules, participation above 1, sizes beyond the pinned bounds.

Error contract

Identical rules in all four languages: Python ValueError, C++ std::invalid_argument (std::domain_error for the AC validity condition), Rust Err(EtradeError) with no panics, Java IllegalArgumentException; solver failures are reported separately. No function returns NaN or infinity from valid finite inputs.

Reference papers

Almgren & Chriss (2000), Journal of Risk; Avellaneda & Stoikov (2008), Quantitative Finance; Perold (1988) and Wagner & Edwards (1993) for the shortfall decomposition and its naming; Guéant, Lehalle & Fernandez-Tapia (2013) for the inventory-capped variant behind q_max; Obizhaeva & Wang (2013) for transient impact; Almgren & Lorenz (2007) for adaptive execution; Welch (1947) for the A/B test; MiFID II Art. 17/27, Reg NMS Rules 605/606 and SEC Rule 15c3-5 in the LEARN guide's regulatory section.

Units and what is out of scope

tau, dt, T in an abstract time unit (bundled sets use one trading day); sigma is arithmetic (currency per share per √time); prices may go negative; AC shares are fractional, A-S fills are one unit. Ticks, fees, latency and informed flow are stylised switches in the market-making simulator, not a matching engine. Not covered yet: venues, lots, an order book, hedging and risk limits, calendars, and any fit of the impact parameters eta, alpha, gamma_p and Y to real parent orders.

Quick start

git clone https://github.com/AshJha0/electronic-trading.git
cd electronic-trading

# Python (3.11+)
pip install -e "python[dev]"
python python/demo.py
pytest python                                   # 575 tests

# C++ (C++26, CMake >= 3.25; GCC 14+, recent Clang, MSVC /std:c++latest, LLVM Clang on macOS)
cmake -S cpp -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release               # 191 tests

# Rust (stable, MSRV 1.78)
(cd rust && cargo test --release && cargo run --release --example demo)   # 290 tests

# Java (JDK 25 LTS, Maven)
(cd java && mvn verify && mvn -q exec:java)  # 333 tests
